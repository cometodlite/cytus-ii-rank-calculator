# CYTUS II 시험 편성 데이터 감사 (초안)

## 범위와 상태

이 감사는 v1.3의 228 슬롯 범위를 **5개 독립 시험 유형, 72개 등급, 288개 슬롯**으로 바로잡았습니다.

| 시험 유형 | 등급 수 | 슬롯 수 | 현행 저장소에 있는 곡 편성 |
|---|---:|---:|---:|
| B-DCT Standard | 15 | 60 | 60 |
| B-DCT SV | 13 | 52 | 52 |
| B-DCT STT | 14 | 56 | 56 |
| DCT Standard | 15 | 60 | 0 |
| DCT MSTT | 15 | 60 | 0 |
| **합계** | **72** | **288** | **168** |

`chart_slots.csv`는 288개 슬롯을 한 행씩 기록합니다. 각 행에 시험 유형, 등급, 슬롯, 잠정 난이도 목표, 현행 곡명, 현재 코드의 채보 추정값, 채보 종류, 변형, 게임 버전, 실제 레벨, 해금 조건, 출처, 확인일, 검증 상태를 둡니다. `song_id`는 공개된 데이터에서 확인할 수 없어 비워 두었습니다. `catalog_song_key`는 카탈로그 팩/제목을 이용한 작업용 후보 키일 뿐, 게임의 정식 ID나 확정 별칭이 아닙니다.

현재 수치는 다음과 같습니다.

- 현행 B-DCT 168개 슬롯에는 곡명이 기록돼 있습니다.
- DCT Standard와 DCT MSTT는 각각 60개 빈 슬롯입니다. 계산기의 사용자 수동 선택 기능은 등급별 편성 원본을 제공하지 않습니다.
- 288개 행 전부 `PENDING`입니다. 현행 HTML은 실제 차트 레벨·해금·게임 버전·안정적인 곡/채보 ID를 기록하지 않으므로 곡명만으로 슬롯을 검증 완료 처리하지 않았습니다.
- `current_chart_difficulty_assumption`은 현행 앱이 정해진 등급/슬롯에 따라 HARD 또는 CHAOS를 골라 표시하던 규칙을 재현한 참고값입니다. 실제 수록 채보로 검증된 사실이 아니며 `chart_difficulty`에 복사하면 안 됩니다.
- 현행 B-DCT 곡명 중 34개는 둘 이상의 유형에 반복됩니다. 유형 간 동일 채보 중복 금지 정책과 충돌한다고 확정할 수는 없습니다. 채보 종류·변형·버전이 미상이고 다른 난이도 사용은 허용되므로, 실채보 ID 확보 후 판정해야 합니다.
- 카탈로그 정확 제목을 찾지 못하는 곡명 표기(예: `Chrome VOX` / `Chrome V0X`)와 리믹스 구분(예: `Fireflies`)은 별칭으로 자동 정규화하지 않았습니다.

## 시험별 결정 반영

- B-DCT Standard 1~3단의 기존 곡 배정은 유지 대상으로 표시했습니다. 감사 전에는 실제 레벨 목표를 만들거나 교체 후보를 제시하지 않습니다.
- B-DCT Standard 4단 이후, SV, STT에는 v1.3의 단계별 목표 레벨을 `target_level`에 잠정 설계값으로 기록했습니다. 이는 실제 슬롯에 대한 검증 결과나 자동 편성안이 아닙니다.
- DCT Standard와 DCT MSTT는 각각 다른 60행 편성표를 가집니다. v1.3의 DCT 레벨 구간은 두 유형에 임시 참고값으로만 반복 기록했고, 두 유형의 목적에 맞는 독립 목표 설계는 미확정으로 명시했습니다.
- 동일 곡의 다른 채보 사용은 허용입니다. `VERIFIED` 행끼리 동일한 `(song_id, chart_difficulty, chart_variant, game_version)`가 시험 유형을 가로질러 재사용되는 경우 검증기가 오류를 냅니다.
- MSTT 산식과 공식 합격 판정은 이 감사 범위 밖이며 계속 보류 상태입니다.

## 보조 출처 샘플

`source_samples.csv`에는 v1.3에서 참고한 10곡의 커뮤니티 위키 표기 레벨과 출처를 보관했습니다. 이는 해당 곡의 공개 위키 표기를 확인했다는 뜻일 뿐, 288개 슬롯의 검증이나 공식 게임 데이터 인증이 아닙니다. 특히 KANATA의 CRASH는 레벨 12가 아니라 `β`로 따로 표기됩니다. 원문 페이지에서 특정 난이도가 보이지 않으면 빈칸으로 두었으며, 부재를 의미하지 않습니다.

## 검증기

프로젝트 루트에서 실행합니다.

```sh
python3 tools/validate_audit.py
```

검증기는 시험별 슬롯 수·등급별 4슬롯, 슬롯 ID 중복, 상태값, `VERIFIED` 행의 필수 메타데이터와 날짜, 유형 간 동일 채보 중복을 확인합니다. 검증 결과는 `VERIFIED`가 아닌 행을 유효한 편성으로 승인하지 않습니다.

## 다음 조사 후보

1. 실제 게임 화면/공식 게임 자료에서 곡과 난이도를 각각 대조하고, 식별 가능한 안정 ID 또는 재현 가능한 곡 식별 규칙을 기록합니다.
2. 우선 기존 편성의 대표 사례(예: Gravity, KANATA, Fireflies, Chrome VOX)를 확인해 현행 곡명과 실제 채보가 같은지, HARD/CHAOS 추정이 맞는지 대조합니다.
3. B-DCT Standard 4단 이후의 목표 상승 완화 후보를 실제 레벨과 대조합니다. 1~3단은 명백한 오류가 발견될 때만 별도 검토합니다.
4. DCT Standard와 MSTT는 같은 곡을 복사하지 말고 독립적으로 후보를 수집합니다. 유형 간 동일 채보 중복은 ID 검증 후 제거합니다.
5. 해금 조건, 게임 버전, 패턴/TP 특성 및 출처가 확인된 행만 `VERIFIED`로 바꿉니다. 불충분하면 `PENDING`을 유지합니다.
